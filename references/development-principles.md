# 底层开发思维与版本管理

> 阶段 0 立项选型、阶段 3 实施时读取。

## 底层开发思维（始终遵循）

坚决杜绝闭门造车、重复造轮子：

1. 启动项目或制定较大方案前，优先去 GitHub 查找同类项目、文档、实现思路和源码
2. 有成熟现成项目时，优先评估 license、维护状态、安全风险和适配成本后复用
3. 简单 bug 修复、明确小改动或离线任务可不强制调研
4. 多检索、多看、多拆解学习开源项目，可复用内容直接取用，有参考价值的方案借鉴参考
5. 多套开源方案交叉对比，取优势、剔除缺陷糟粕

## 版本管理

后续用户有新需求时，建立机制防止项目被改坏：用 git 仓库做版本管理，每次大改动前提交，方便回退。如果项目还没有 git 仓库，初始化一个。

- 每个 feature 完成并过门禁后提交一次
- 提交信息写清「做了什么」
- 用户有新需求前，先确认当前版本已提交

## 部署与托管

- 部署：按用户指定的服务器/平台部署（用户没指定就问，不要擅自选）。
- 域名/托管：优先考虑不需要单独买域名的插件或托管平台（如各大平台自带的二级域名/静态托管），实在没有合适的，再提示用户购买。
- 部署后验证可访问，再向用户汇报。
