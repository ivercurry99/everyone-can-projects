# 进度记忆管理

> 阶段 2 初始化、阶段 5 收尾、恢复会话时读取。用户无需懂，你自动执行。

## 核心目标

保证换会话、换设备后能无缝继续，用户不用自己记任何东西。

## 实现方式（按宿主能力选择）

- 宿主有记忆系统 → 用记忆系统。
- 宿主没有 → 在项目根目录维护一个 `PROGRESS.md`（或等价进度文件）作为唯一事实来源。

无论哪种方式，都遵循同一套纪律：

1. 进度文件只做索引，每个主题一行，不在索引里堆正文
2. 以 150 行或 20KB 作为日常软上限，永远不要逼近加载上限
3. 每个子文件只保存一个明确主题
4. 写入前先检索现有记忆：能更新旧记录就不重复新增
5. 新结论推翻旧结论时，直接修正旧记录，不保留互相矛盾的两个版本
6. Git、代码和项目文档中已明确存在且容易重新获得的内容，不重复抄进记忆
7. 密码、密钥、Cookie、Token、私钥等秘密永不写入记忆
8. 注意多分支任务的记忆隔离与必要信息共享

## 初始化（阶段 2 执行）

- 先确认记忆系统处于开启状态：如果没开启、或不确定，停下来告诉用户怎么开启，不要往下执行。
- 检查现有进度文件，先读再写，不要直接覆盖。
- 完成后汇报：当前用哪种记忆方式、创建或修改了哪些文件、发现了哪些重复/冲突/风险。

## 三层分类（信息放哪层）

把信息按三层归档，别放错位置：

1. **必须确定性执行的安全/操作限制** → 建议放进宿主的安全配置（settings / permissions / hooks），未经用户确认不要直接改。
2. **每个会话都该遵守的项目规则、约束、工作习惯** → 写进项目指令文件（宿主各自的等价配置文件），保持简短。
3. **只有相关任务出现时才需要的事实、进度、经验、资料** → 写进进度记忆，按主题整理。

初始化时检查现有指令文件、规则文件和进度记忆，把疑似放错位置的内容列出来，用户确认后再改。

## 阶段收尾：同步进度

每个阶段收尾，检查本段会话，把跨会话后仍有价值的内容同步进进度文件：

- 当前任务进行到哪里
- 已确认的结论
- 做了哪些重要决定、每项决定背后的原因或证据
- 尝试过但失败的方案、失败原因
- 修改了哪些关键文件
- 当前测试结果
- 尚未解决的风险或问题
- 下一步最具体的行动

## 恢复会话

用户说「接着做」时，先定位进度文件，再读取与当前任务直接相关的部分，用两三句话告诉用户：当前进度、已确认的关键决定、下一步行动、信息来自哪里。如果某内容没有记录，明确说「没有记录」，不要凭印象猜测。

## 上下文压缩

如果宿主支持上下文压缩，只保留：当前目标、已完成和未完成事项、已修改文件、关键设计决定及原因、失败方案及其证据、测试结果、未解决风险、下一步验证计划。删除闲聊、重复输出、过时计划和失效尝试。
