# 多模型 / 多 Agent 适配策略（Fallback Strategy）

> 本技能的核心承诺：**无论什么模型、什么宿主，都能稳定出结果。**
>
> 实现思路：**"能力检测 → 走最优路径；能力缺失 → 自动降级，等价完成。"**
> 任何一环都不是单点依赖。

---

## 1. 能力矩阵（= 有啥能力走啥路径）

| 能力 ID | 有它时怎么做 | **没它时怎么降级**（关键！） | 对模型能力要求 |
|---|---|---|---|
| `subagents` | 五个角色并行跑，调度员路由 | **单人按角色切换，串行完成；门禁 checklist 一项不少**；开发者≠测试员、架构师≠审查员 | 弱模型也能做：只要能"读文件+切换语气" |
| `memory_system` | 用宿主记忆系统持久化进度 | **用项目根 `PROGRESS.md` 作为唯一事实来源**；每阶段写盘、每会话先读 | 零要求：会写文件即可 |
| `brainstorm_skill` | 调用头脑风暴技能做需求澄清 | **等价开放式提问 + 默认值补齐**；最多问 5 个问题，其余默认 | 弱模型也能做：按预设问题问就行 |
| `aesthetic_skill` | 调用去 AI 味技能做打磨 | **逐项人工审查 checklist**（见下节）：通用占位符 / 模板套话 / 语气一致性 | 中等：需要读懂中文文案 |
| `web_fetch` | 上 GitHub 找开源方案复用 | **跳过去开源复用环节**，按本地常识给出默认选型并告知用户 | 无要求 |

**怎么检测能力**：先"乐观尝试"一步，失败就切降级路径，绝不因缺一个能力就卡住。

示例伪代码（Agent 执行时遵循）：

```
1. 先尝试：调用子智能体跑架构师角色
   - 如果 30s 内没成功 / 宿主报错 → 降级：自己切换成架构师角色，读 phases/01-design.md 模板开始写
2. 写完架构 → 记到 phases/01-design.md
3. 之后无论任何角色、任何宿主，都只认 phases/ 里的文件。
```

## 2. 弱模型保底：去 AI 味 Checklist

没有审美技能时，按这个 checklist 一条条过一遍，绝大多数"AI 模板味"就能去掉：

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 无通用占位符 | 没有"欢迎使用本系统""这里放你的内容""请联系管理员"这类套话 |
| 2 | 语气一致 | 同一文档/页面里，不一会儿严肃、一会儿口语、一会儿 emoji 乱飞 |
| 3 | 有真实示例 | 列表/表格/代码至少有一项具体示例，而不是全是 `TODO` |
| 4 | 排版合理 | 标题层级不乱、段落不空、中文与英文之间有空格 |
| 5 | 不夸大 | 没有"业界领先""革命性""下一代"等无证据的营销词 |
| 6 | 图标/图片有来源 | 有占位图时明确写 `assets/` 路径，不乱引外链 CDN |

**执行方式**：每打磨完一个文件，在 phases/04-review.md 里勾上这 6 项（通过/未通过+原因）。

---

## 3. 多模型稳定性：防止"跳步骤"

弱模型（包括但不限于 7B / 8B / 小型本地模型）常跳过门禁或直接写代码。
强制保护机制：

1. **Checklist 显式化**：每个阶段入口，Agent 必须先打印「本阶段要做的 3-5 件事」，做完再打印「完成的 n/n」。
2. **不输出就不算完成**：所有中间结论必须写入项目内的文件（phases/ 或 PROGRESS.md），不能只靠聊天记录。
3. **调度员最后签字**：每个 feature 必须有「调度员判定门禁是否通过」的明确一行文字，没写就不算。
4. **单轮指令短小**：一次只让模型做一件事（例如"现在只写 phases/01-design.md"），不要给超过 3 个并列任务。

---

## 4. 错误兜底：任何阶段失败，都能续做

兜底的三条铁律（Agent 必须遵守）：

1. **先保存再报错**：出错时先把已完成部分写进文件 / PROGRESS.md，再报错。
2. **只重做失败阶段**：错误报告里必须明确说「当前卡在哪一阶段、哪些文件已保留、下一条命令是什么」。
3. **不重复造轮子**：之前跑通的阶段绝不重跑，避免回滚式返工。

错误报告模板（Agent 出错时照抄）：

```
❌ 阶段 X 失败
- 原因：[一句话]
- 已保留的产物：phases/01-design.md, PROGRESS.md, ...
- 如何续做：重新发起该阶段任务即可，不会覆盖已有文件（已有文件默认跳过）
- 建议的下一步：[一条具体的行动]
```

## 5. 宿主兼容性声明（≥ 最小集合即可运行）

| 宿主 / 框架 | 最低能力集合 | 预期效果 |
|---|---|---|
| TRAE（本宿主） | 读写文件 + 提问 + 执行命令 | 全能力，最优路径 |
| 普通 CLI 聊天 Agent | 读写文件 + 执行命令 | `memory_system` 降级到 PROGRESS.md；其他能力等价完成 |
| Cursor / Copilot Chat 等 IDE Agent | 读写文件 + 提问 | 无 `web_fetch` 时跳过 GitHub 复用；其余正常 |
| 只有文本接口的小模型 | 纯文本输出 | **需手动将 Agent 输出落地为文件**；其余流程可按 7 份文档 / 五道门禁清单逐项手工完成 |

**结论**：只要宿主能「读写文件」，本技能就能完整跑通。其它能力全是可选增强。
